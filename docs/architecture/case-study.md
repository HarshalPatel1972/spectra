# Case Study: Scanning Spectra with Spectra

One of the foundational tenets of the Spectra project is radical transparency. To prove the efficacy of the Spectra parsing engine, the CycloneDX generation, and the QRS calculation, we continuously scan the `spectra` repository itself.

## The Results
The `spectra` repository has an aggregate Quantum Risk Score of **8/100 (SAFE)**.

You can view the full, official CycloneDX CBOM generated by the latest build of Spectra here: `spectra-cbom.json` in the root of the repository.

## Why isn't the score 0?
An 8/100 score indicates the presence of low-risk cryptography. In our case, this is entirely intentional. The `spectra` repository contains a `testdata/` directory used by our unit tests. 

This directory contains specifically crafted files with deprecated cryptography (such as `testdata/vulnerable.go` which imports `crypto/md5` and `crypto/sha1`) to ensure our AST parser correctly identifies them during continuous integration testing.

Spectra successfully identified its own test fixtures, mapped them to the correct lines of code, and calculated the localized QRS penalty, resulting in the aggregate score of 8/100.

## The Process
We run Spectra against its own source code as a mandatory step in our GitHub Actions CI pipeline. If the QRS score ever exceeds 15/100 (allowing room for additional test fixtures), the build will automatically fail.

This ensures that Spectra itself never introduces unintentional quantum-vulnerable cryptography into your supply chain.
